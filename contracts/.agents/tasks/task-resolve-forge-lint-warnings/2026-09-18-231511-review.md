# Resolve all 93 forge-lint warnings across the RetroPick protocol — semantic review (v1)

This change clears every one of the 93 `forge build` lint warnings across the bonding-curve launchpad, the Uniswap v4 hook, the cross-chain migration doorway, and three Doorway test files. The approach splits cleanly into two buckets: genuine issues fixed in code (missing zero-checks and access-control/arithmetic events on the Doorway, an uninitialized local and a divide-before-multiply precision bug in the hook, a `nonReentrant`-first modifier reorder on four functions, and swapping test `block.timestamp` reads for `vm.getBlockTimestamp()`), and provable false positives suppressed with per-line `// forge-lint: disable-next-line(...)` directives that each carry a concrete, code-specific justification. No behavioral semantics were changed beyond the additive fixes, and no reentrancy guard or value-handling path was weakened.

Watch for: nothing blocking. The one deliberate deviation from the plan — `RetroPickBondingCurveV1` constructor `pairToken_` is suppressed rather than zero-checked because `address(0)` is the native-ETH sentinel (confirmed) — is correct. Every ETH-send and reentrancy suppression was traced to a real guard or CEI ordering (confirmed). One residual solc `Warning (2018)` on `exemptFromSnipeTax` is a compiler mutability hint, not a forge-lint entry, and is correctly out of scope (confirmed).

**Verdict**: APPROVED

## High-level view

The Doorway fixes are the cleanest: real zero-address `require`s on the constructor and the two access-control setters, a new `OwnershipTransferred(old, new)` event wired into both the interface and `transferOwnership`, and four suppressions on setter assignments whose old→new events already fire on the line immediately above (a linter heuristic gap, not a missing event). The one `block-timestamp` suppression guards a multi-block cancellation delay where seconds of miner drift are immaterial.

The hook carries the only arithmetic change worth scrutiny: the `afterSwap` buyback accrual was rewritten from a divide-then-multiply chain into `unspecified * hookFeeBps * (BASIS_POINTS - protocolFeeShareBps)` followed by a single `FullMath.mulDiv(..., buybackBurnBps, BASIS_POINTS^3)`. This is arithmetically equivalent to the intended formula, strictly more precise (all multiplications precede the one division), and overflow-safe with headroom. The `int128`/`uint128` casts around it are bounded by the `MAX_TOTAL_TRADE_FEE_BPS = 2000` cap enforced at `_registerPool`, and each cast suppression names that bound.

The value-handling suppressions across the curve, factory, and executor are the security core, and all hold: every `arbitrary-send-eth` recipient is either an immutable protocol contract, a state-recorded fee recipient validated non-zero, or a caller-argument recipient checked `!= address(0)` in the entry function; every `reentrancy-events`/`reentrancy-no-eth`/`reentrancy-balance` suppression sits behind either `nonReentrant`, `onlyFactory`, or a CEI ordering where state is finalized before the external call. The `nonReentrant onlyOwner` reorders are safe because `onlyOwner` (Ownable2Step) only reads owner and reverts.

The build is clean at zero forge-lint warnings and the full suite passes 45/45, independently re-confirmed.

### Doorway: zero-checks, ownership event, and adjacent-emit suppressions

The constructor now rejects zero `_treasury`/`_relayer`/`_guardian`, and `setRelayer`/`setGuardian` reject zero inputs (confirmed at lines 122–124, 424, 448). `transferOwnership` gained a real `OwnershipTransferred(previousOwner, newOwner)` event, declared in `IRetroPickDoorwayV1.sol:109` and emitted old→new before the assignment.

The four remaining `missing-events-access-control`/`missing-events-arithmetic` suppressions (setRelayer, setGuardian, setFee, transferOwnership) each sit on the state-assignment line, one line below an `emit XUpdated(old, new)`. The `block-timestamp` suppression on `cancelMigration` guards a `CANCELLATION_DELAY` window where seconds-scale miner drift cannot bypass a coarse delay.

### Hook afterSwap: divide-before-multiply rewrite and the fee-cap-bounded casts

The precision fix is the one arithmetic change requiring proof. The intended buyback accrual is the creator's post-protocol bucket times the burn rate: `unspecified * hookFeeBps * (BASIS_POINTS - protocolFeeShareBps) * buybackBurnBps / BASIS_POINTS^3`. The rewrite computes `buybackScaled = unspecified * hookFeeBps * (BASIS_POINTS - protocolFeeShareBps)` then `FullMath.mulDiv(buybackScaled, buybackBurnBps, BASIS_POINTS * BASIS_POINTS * BASIS_POINTS)` (lines 494–497). All three multiplications precede the single division, so no floored quotient feeds a later multiply — arithmetically equivalent to the intended formula and strictly more precise than the original divide-first chain.

Overflow is safe with headroom: `unspecified` is an `int128` BalanceDelta component normalized non-negative, so `<= 2^127 ≈ 1.7e38`; `hookFeeBps <= 1000` and `(BASIS_POINTS - protocolFeeShareBps) <= 10000`, giving `buybackScaled <= ~1.7e45`, far under `uint256` max (`~1.15e77`). `FullMath.mulDiv` carries the final `× buybackBurnBps` in 512-bit space, so the intermediate cannot overflow.

The `int128(uint128(totalAmount))` return cast and the `uint256(uint128(unspecifiedAmount))` cast are both bounded: `_registerPool` enforces `creatorTaxBps + hookFeeBps <= MAX_TOTAL_TRADE_FEE_BPS (2000)` (confirmed at line 359), so `totalAmount = unspecified * (hookFeeBps + creatorTaxBps) / BASIS_POINTS <= unspecified / 5`, which stays well inside `int128`. Each suppression comment names this exact bound.

`missing-zero-check` on the constructor `initialOwner_` was fixed in code (`if (initialOwner_ == address(0)) revert ZeroAddress();`), matching the file's existing revert style alongside the poolManager/feeEscrow/protocolFeeRecipient checks. The two `uninitialized-local` locals (`buybackSpent`, `tokensLocked`) are now explicitly `= 0` (lines 726–727). `rescuePoolFees` was reordered to `nonReentrant onlyOwner` so the guard engages first (confirmed at line 578–580).

### Value handling: arbitrary-send-eth and reentrancy suppressions across curve/factory/executor

These are the security-critical suppressions and all trace to a real guard or CEI ordering.

In `RetroPickBondingCurveV1`, `_sendQuote`'s native ETH send is suppressed with the claim that every caller validates `recipient != address(0)` and runs under `nonReentrant`/`onlyFactory` with reserves updated first. Spot-checked: `sell` and `graduate` both `revert ZeroAddress()` on a zero recipient and decrement `trackedQuote`/`trackedTokens` before calling `_sendQuote` (confirmed). The `reentrancy-events` suppressions on `buy`/`sell`/`graduate`/`_sweepFees`/`rescueFees` and the `reentrancy-no-eth` on `_creditQuote`/`buybackVault.lock` all sit behind `nonReentrant` or `onlyFactory` with state finalized before the external call. `graduate` is deliberately not `nonReentrant` (so it stays callable from inside `buy`'s guarded scope) but sets `graduated = true` and zeroes reserves before any transfer, which the suppression comment states accurately.

The `pairToken_` deviation is correct: `address(0)` is the native-ETH sentinel read by `isNativeQuote()`, so a zero-address `require` would break every native launch. Suppressing with that justification rather than "fixing" it is the right security judgment.

In `RetroPickLaunchFactoryV1`, both `arbitrary-send-eth` sends resolve to trusted recipients: `graduationExecutor` is owner-configured and checked `!= address(0)` in `createGraduatedPool` (which is `nonReentrant`), and `_payLaunchFee` reads `recipient` from `memeHook.protocolFeeRecipient()` and reverts on zero before sending the fixed `launchFee` (confirmed at lines 1226, 1486–1487). The combined `unused-return, reentrancy-balance` suppression on `curve.graduate` is sound — the factory intentionally discards the curve's nominal quote and credits the measured balance delta instead (more robust for fee-on-transfer quote assets), both callers are `nonReentrant`, and the curve is protocol-deployed. The three `nonReentrant onlyOwner` reorders are safe: `onlyOwner` only reads owner and reverts.

In `RetroPickGraduationExecutorV1`, `_sweepResidualBalance`'s ETH send goes to either the immutable `locker` or the `protocolFeeRecipient` forwarded from the `onlyFactory` mint path — never caller input. The two `reentrancy-events` emits report the post-transfer `swept` result so they cannot precede the call, and the contract holds no cross-transaction state. The `_approvePermit2` `uint160(amount)` cast is bounded by the `amount0Max/amount1Max > type(uint128).max` overflow guard in `mintFullRangePosition` (confirmed at line 98), and `uint48(block.timestamp + 300)` cannot overflow for centuries. The `uint8(Actions.*)` casts pack v4 library action constants far below 255.

### The GraduationGuard int128 bound and the BuybackVault emit move

`MAX_SEED_AMOUNT = uint256(uint128(type(int128).max))`: `int128.max` is non-negative, so both the `uint128` narrowing and `uint256` widening are exact, matching the pre-existing comment that v4 narrows liquidity with `SafeCast.toInt128` so the signed bound is the real limit.

`RetroPickBuybackVaultV1.release` moves `emit Released` before the escrow credits — the only emit reorder in the change. It is honest: `vestedUnreleased` is zeroed and `totalReleased` advanced before the emit, and `release` is `nonReentrant`, so the logged amounts are final. Clears the lint via a real reorder rather than a suppression.
