# src/v1 + src/v2 split of the RetroPick contract tree (v1)

The 15 existing RetroPick source files were relocated from `src/*` (with `hooks/`, `interfaces/`, `libraries/` subtrees) into `src/v1/`, and a full copy was placed in `src/v2/` with every `V1`/`v1` token rewritten to `V2`/`v2`. The intent is a side-by-side versioned layout inside the single `src` compile root: `src/v1` is the untouched V1 protocol, `src/v2` a faithful, self-consistent V2 rename ready to diverge later. The six Doorway test files were repointed from `../../src/...` to `../../src/v1/...` with no symbol or revert-string edits. Both trees compile together against Solc 0.8.26 (via_ir, cancun), the forge-lint `^warning\[` count is 0, and all 45 tests pass.

Watch for: one non-versioned interface name, `IERC721ReceiverLike`, is declared identically in both trees (`src/v1/interfaces/IRetroPickLaunchpadV1.sol` and `src/v2/interfaces/IRetroPickLaunchpadV2.sol`) — a latent naming collision that compiles today only because the two trees never share a compilation unit (confirmed). Everything else verified clean.

**Verdict**: APPROVED

## High-level view

The move was done with `git mv`, so the v1 relocation surfaces as renames in `git status`. Note that `origin/main` and `HEAD` are the same commit and the entire task lives in the working tree; a raw `git diff origin/main -- src/v1` therefore also folds in the pre-existing, uncommitted V2→V1 rebrand edits that predate this task (visible as `RetroPickV2LauncherToken` → `RetroPickLauncherTokenV1` etc.). Those are out of scope per the briefing. Judged on the resulting tree, `src/v1` is internally self-consistent: zero non-Uniswap `V2`/`v2` tokens remain.

The v2 tree is a mechanical token-swap copy. Every one of the 15 v2 files is byte-identical to its v1 counterpart once `V1`↔`V2` and `v1`↔`v2` are normalized away — verified pairwise, all 15 match. No `V1`/`v1` residue survives in `src/v2`, and the replacement did not over-reach: no `V22`, `V2V2`, or `V3` artifacts, and Uniswap `V4`/`v4` naming is untouched in both trees. Relative imports inside v2 resolve within v2; no v2 file imports from v1.

Top-level declared names are disjoint between the trees for every versioned symbol, so there are no compile-breaking contract-name collisions — with the single exception of `IERC721ReceiverLike`, which carries no version token and so appears in both. It compiles because no unit imports both, but it is the one naming asymmetry a future merge into a shared file would trip over.

Tests still target v1 only. The diff against `origin/main -- test` is exclusively import-path rewrites; symbols and revert strings are unchanged, and no test references `src/v2`.

### Provenance of the v1 content deltas

`git log origin/main..HEAD` is empty and `git status` shows every change as uncommitted (renames `R`/`RM` for v1, additions `A` for v2). Because base and HEAD are identical, `git diff origin/main` cannot separate this task's move from the rebrand edits already sitting in the working tree when the task began. The `RM` files (LaunchDeployer, LaunchLocker, LauncherToken, the two interface files under `interfaces/`, and the two libraries) show `RetroPickV2*`→`RetroPick*V1` symbol and comment rewrites in addition to the path move. Per the briefing and `context.json`'s `distinct_v1_symbols` list, the V1 names are the intended task baseline; those symbol rewrites are the pre-existing rebrand work, not part of the restructure. The restructure's own contribution is the path move plus the test import-path fixups, which the rename detection captures cleanly. Judging the tree as it stands rather than the mixed diff, `src/v1` is self-consistent (see below), which is what matters for correctness regardless of when each edit landed.

### v2 is a faithful token-swap copy

Normalizing `V1→@@ / v1→##` in each `src/v1` file and `V2→@@ / v2→##` in its `src/v2` counterpart yields identical text for all 15 pairs. That is the strongest available evidence that v2 is a pure rename with no accidental behavioral drift: no logic, revert conditions, or struct layouts changed, only version tokens. Revert-string literals moved with the rename (e.g. `"RetroPickDoorwayV1: ..."` → `"RetroPickDoorwayV2: ..."`), consistent with the intent.

The replacement was neither under- nor over-eager. `grep` for `V1|v1` in `src/v2` (excluding `V4|v4`) returns zero; the same search for `V2|v2` in `src/v1` returns zero. No `V22`/`v22`/`V2V2`/`V3` artifacts anywhere in `src`, and no `V5`/`v5` or `@uniswap/v2` — the Uniswap V4 imports and type names survived intact in both trees, which was the main risk of a blind `v1→v2` token sweep.

### No cross-tree imports, no collisions that break compile

No file under `src/v2` imports from `src/v1` (grep for `/v1/` or `v1.sol` in v2 imports returns zero), so the v2 tree is closed over itself. Comparing the sets of top-level `contract`/`interface`/`library`/`abstract contract` declarations, every versioned name differs by exactly its `V1`/`V2` suffix and the intersection is a single entry: `IERC721ReceiverLike`. That name has no version token, so the rename left it identical in both trees. Because `src` is the compile root, both declarations are in scope during the same `forge build`; it compiles only because Solidity permits duplicate top-level names across files that are never pulled into one compilation unit, and nothing imports both `IRetroPickLaunchpadV1` and `IRetroPickLaunchpadV2` together. It is a latent hazard rather than a current defect — flagged as the sole issue above.

### Build, lint, and test verification

`forge build --force` reports "Compiler run successful with warnings" over 127 files. The only warnings are the two documented benign solc `Warning (2018)` (state mutability can be restricted to view) on `exemptFromSnipeTax` at `RetroPickBondingCurveV1.sol:813` and its faithful copy `RetroPickBondingCurveV2.sol:813`. The v1 one is a rename of the unmodified HEAD file (pre-existing, left as-is to keep v2 faithful); the v2 one is its exact copy. Neither is counted by the forge-lint metric: `forge build --force 2>&1 | grep -cE '^warning\['` returns 0. `forge test` runs 5 suites, 45 passed / 0 failed / 0 skipped, matching the baseline — including the invariant suite (64 runs × 4096 calls, 0 reverts).

### Tests target v1 only

The `git diff origin/main -- test` is entirely import-path rewrites across the six Doorway test files: `../../src/RetroPickDoorwayV1.sol` → `../../src/v1/RetroPickDoorwayV1.sol` and the matching `interfaces/` path. Imported symbols (`RetroPickDoorwayV1`, `Migration`, `MigrationStatus`, `Attestation`) and any revert-string assertions are unchanged. No test file references `src/v2`, so the V2 tree is compiled but not yet exercised — expected at this stage, and worth remembering when v2 starts to diverge, since it currently has no test coverage of its own.
