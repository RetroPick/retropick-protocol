# ADR-CE02 — atomic treasury binding and canonical V2 adoption
Status: OWNER-ACCEPTED FOR SCOPED CANONICAL IMPLEMENTATION SUBJECT TO QUALIFICATION (2026-11-02). Explicit owner response: "Accept for canonical implementation subject to qualification". This accepts the described canonical implementation work; it grants no release, deployment, dependency upgrade or unrelated economic change authority.

Replace the PR44 shared predicted-address helper with an alternate factory-only builder and a separately qualified treasury deployer. The actual token, creator, curve and authenticated router exist before treasury creation. Deployer must create a distinct destination for each router/token, enforce factory/community-builder authorization, and bubble every failure. Builder substitutes actual destination into registry policy, binds registry, then unchanged factory seals curve. No public post-launch selection, mutable initializer or salt assumption. Immutable implementation/codehash pinning must be accompanied by a nonproxy deployer review.

Version1 envelope preserves legacy Config semantics in the old builder. New mode permits creator/contributor/treasury only, requires zero treasury input placeholders, and creates the actual beneficiary atomically. Existing factory commitment mechanism binds builder code and exact input bytes; event links generated address and registry. Existing factory runtime and source stay unchanged during this experiment. Constructor checks must not require registry/final curve readiness before they exist; runtime claims require complete sealed chain.

The binding-only probe is a noncustodial test seam forwarding its own legitimate credit to a fixed receiver. It proves neither secure treasury custody nor spending delay and must never be deployed or promoted. Full closure requires real Vault/Timelock/Deployer, all hostile/failure paths, per-asset conservation, callback tests, source/build hashes and separate independent implementation review.

Candidate custody/governance retains approved isolated OZ5.4.0 closure, fixed72h delay, seven-day inclusive expiry, permanent open execution, governed proposer/canceller changes, no renunciation/admin removal or emergency spender, immutable source, quarantined surplus and earned-fund-only spending. Existing router remains sole fee entitlement ledger. No new fee, liquidity access or external venue right.

Canonical promotion is a later separate gate: qualify real treasury first, owner acceptance is now recorded above; promote modules and existing tested opt-in factory/curve/interface/v4 fee-disable changes. Preserve legacy mode, historical source/ABIs/deployments, old tests and V3. Use stage-specific approved-change checks without weakening frozen baseline tool. No actual deployment or automatic merge.
