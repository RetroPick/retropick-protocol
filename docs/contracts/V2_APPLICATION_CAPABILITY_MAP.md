## 2. Contract interaction graph

Notation: `--calls-->` (direct external call), `==auth==>` (authority gating). Assets: quote = native MON (`address(0)`) or admitted ERC20; base = launch token.

### 2.1 Deployment edge: Factory → LaunchDeployer → Token + Curve

```
creator --launchToken(TokenParams,id,pairToken,venue)--> Factory   (msg.value == launchFee)
Factory --deployLaunch(LaunchDeployment)--> LaunchDeployerV2      (onlyFactory)
LaunchDeployer --new--> RetroPickBondingCurveV2(pairToken, creatorFeeRecipient, factory, ...)
LaunchDeployer --new--> RetroPickLauncherTokenV2(..., curve, factory, supply)  // mints full supply to curve
Factory --initialize(token)--> Curve                                (onlyFactory; fixes reservedTokens)
Factory --exemptFromSnipeTax(deployer[, creatorFeeRecipient])--> Curve
Factory --registerLaunch(token,curve,venue,poolFee,tickSpacing)--> Coordinator (onlyFactory)
Factory --payLaunchFee--> protocolFeeRecipient (native, launchFee)
emits: TokenLaunched (curve emits Initialized)
```

- Authority: `launchToken` gated by `canLaunch(originalDeployer)` = `launchEnabled || whitelistedLaunchers[launcher]`; `msg.value != launchFee` reverts `LaunchFeeNotPaid`; `expectedEconomics != bytes32(0)` must equal `coordinator.previewEconomics(id, pairToken, venue)` else `LaunchEconomicsMismatch`.
- Inputs/outputs: returns `(token, curve)`; failures are the full factory error set in §4.1.
- Assets transferred: launch fee (native) out; nothing else moves (token supply is minted to the curve).
- Lifecycle: NotGraduated (curve trading begins immediately).

### 2.2 Registration/binding: Factory → GraduationCoordinator → venue executors

```
Factory ==onlyFactory==> Coordinator.registerLaunch(...)
  reads quoteRegistry.admitted(curve.pairToken(), venue)  -> QuoteAssetConfig (reverts UnsupportedQuote)
  resolves executors(venue) (UNISWAP_V4=0 / KURU=1)
  freezes GraduationPacket {executor, executorCodeHash, quote terms, feePolicy snapshot,
                            protectedLPReceiver = executor.previewReceiver(packet)}
  executor.validateLaunch(packet, totalSupply)
  emits LaunchCommitted(token, venue, keccak(packet))
Coordinator ==onlyFactory==> configureExecutor(venue, executor)  (factory owner path)
Executor binding invariant: executor.coordinator() == coordinator && policyHash() != 0
```

- The packet is the launch-time commitment; nothing in it can change on retry. `previewEconomics` (the `expectedEconomics` preimage) hashes config + quote policy + venue + executor identity + codehash + executor policy hash.

### 2.3 Kuru graduation edge: Coordinator → KuruGraduationExecutorV2 → Kuru Market + Vault + LiquidityLock

```
anyone --factory.graduate(token)--> Factory --secure(token)--> Coordinator (onlyFactory)
Coordinator --secureCurve(token)--> Factory (one-hop callback) --curve.graduate(coordinator)-->
   Curve: sets graduated, sweeps fees, hands trackedQuote + trackedTokens to Coordinator
   emits GraduationSecured(token, quote, launchTokens)   [phase NONE -> GRADUATING]

anyone --factory.createGraduatedPool(token)--> Factory --complete(token)--> Coordinator (permissionless)
Coordinator --approveExact(token/quote -> executor)--> tokens
Coordinator --execute{value: native quote}(packet, quoteAmount, tokenAmount)--> KuruGraduationExecutorV2
  (onlyCoordinator; requires quoteAmount in [graduationThreshold, graduationQuoteCeiling],
   tokenAmount == 500 ether for the pinned policy, msg.value == quoteAmount for native)
Executor:
  - quarantines stray assets to ExecutorDonationLockV2
  - pulls token + quote from Coordinator (exact deltas)
  - baseSeed = Policy.seed(tokenAmount, quoteAmount, phantomQuote)
  - Router.deployProxy(NATIVE_IN_QUOTE for native quote) -> deterministic market + vault (CREATE2)
  - new KuruLiquidityLockV2{salt}(token, quote, market, vault)  -> must equal packet.protectedLPReceiver
  - vault.deposit{value}(baseSeed, quoteAmount, quoteAmount, receiver=lock)
      -> shares = sqrt(baseSeed*quoteAmount) - 1000 minted to lock; assets routed into MarginAccount
  - sends tokenAmount - baseSeed excess launch tokens to lock
  - verifies market params/spread/opening quotes within SEED_TOLERANCE_BPS (5 bps)
  - returns GraduationReceipt {market, vault, lpAsset=vault, seededQuote, seededLaunchTokens,
                               protectedLPReceiver=lock, protectedLPAmount=shares, ...}
Coordinator verifies receipt (hash, destinationIdentity, conservation, receiver identity),
 clears allowances, marks phase GRADUATED, emits GraduationCompleted(token, destinationIdentity, receiptHash)
```

- Assets: quote + base leave Coordinator custody for the market/vault/lock; **nothing returns to any user**; the LP shares and excess tokens are permanently locked (`KuruLiquidityLockV2` has no withdrawal entrypoint).
- Failure conditions: `WrongPhase`, `InvalidPacket` (tokenAmount != 500 ether, quote out of band, receiver mismatch), `InvalidMarket` (deterministic address drift, market params mismatch), `InvalidDeposit` (opening quote tolerance), `EnvironmentDrift` (Kuru environment pin), `BackingDeficit`/`InexactHandoff`/`InvalidReceipt` on the Coordinator side.
- Lifecycle: GRADUATING → GRADUATED (terminal). `complete` is retryable until success (transient failures leave the launch in GRADUATING).

### 2.4 Fee routing: Curve → FeeEscrowV2 / BuybackVaultV2

```
trade fees (quote-denominated, charged on the quote leg of buys AND sells):
  Curve._accrueFees -> quoteFeeBalance (+ buybackQuoteBalance earmark when buybackEnabled) + creatorTaxBalance
sweep (curve.sweepFees, operator-or-creator; auto-run inside graduate):
  protocol slice -> feeEscrow.credit{value} / creditToken(protocolFeeRecipient, ...)
  creator slice  -> feeEscrow.credit*(deployer, ...)
  buyback slice  -> internal swap against curve reserves (bounded by maxInternalPriceImpactBps
                    and reservedTokens floor) then
                    buybackVault.lock(token, tokensLocked, buybackCreatorRecipient,
                                      protocolFeeRecipient, protocolFeeShareBps)
                    emits BuybackLocked
BuybackVault.release(token) [creator or protocol beneficiary only]
  -> feeEscrow.creditToken(creator/protocol recipients, token, ...)   // claim via FeeEscrow
emits: FeesSwept, Released
```

- Escrow is a pull-payment ledger: `balanceOf`/`balanceOfToken` are claims, never auto-sent.
- Buyback lock is a 5-year (`VESTING_DURATION`) weighted-average vest; the split applies to the release while the funding comes out of the creator's slice alone.
- Rescue path (owner-only, wedged quote assets): `factory.rescueCurveFees` → `curve.rescueFees` pays pending fees directly, bypassing escrow, and unblocks graduation.

### 2.5 Uniswap V4 stack (external infra hooks)

```
Factory/Coordinator/V4 executor wiring: PoolManager, PositionManager, Permit2, memeHook, locker
V4 executor execute() (onlyCoordinator):
  poolManager.initialize(poolKey, sqrtPrice)            // hook = RetroPickMemeHookV2
  positionManager.modifyLiquidities(mint full-range -> locker)  // via Permit2 for token pulls
  memeHook.registerPool(...)                             // post-graduation fee policy
Position/LP custody: RetroPickLaunchLockerV2 (PositionManager ERC721 -> locker, permanent)
```

Classification: Permit2 / PoolManager / PositionManager / PositionDescriptor / WETH are **external infrastructure**. The application never calls them: all v4 interactions are protocol-internal to the graduation executor and the hook. `PoolManager.unlock/swap/settle/...` surfaces must not be exposed.

### 2.6 Kuru trading edge: OrderBook ↔ MarginAccount ↔ KuruAMMVault

```
user --deposit(user,token,amount)--> MarginAccount   (native: msg.value==amount; ERC20: approve+pull)
user --addBuyOrder(price,size,postOnly)--> OrderBook --debitUser(user, quote, cost)--> MarginAccount
user --addSellOrder(price,size,postOnly)--> OrderBook --debitUser(user, base, size)--> MarginAccount
taker flow: OrderBook --creditUser(maker, ..., useMargin)--> MarginAccount (or direct ERC20/ETH out)
market orders: placeAndExecuteMarket{Buy,Sell}
  NATIVE_IN_QUOTE market (MON-native launches): buy pays msg.value in an exact bracket; sell msg.value==0
AMM vault: OrderBook <-> KuruAMMVault (vault quotes best bid/ask alongside limit orders;
  vault funds live in MarginAccount under the vault's own account)
cancel: batchCancelOrders / batchCancelOrdersNoRevert --creditUser(locked funds back)--> MarginAccount
emits: OrderCreated, OrderCanceled/OrdersCanceled, Trade
```

- The market owns no custody: every fill/settle routes through `MarginAccount` balances keyed `keccak256(user, token)`, with `address(0)` as native MON.
- The vault's `deposit` (graduation seed) is executor-driven; post-graduation the vault quotes automatically — users never call the vault.

### 2.7 Curve buy/sell → graduation trigger chain

```
buy crosses the reserved allocation:
  Curve.buy -> fills up to sellable, refunds excess, emits CurveBuy(+CurveBuyRefunded)
  -> _tryAutoGraduate: if sellableTokens() == 0 (== realQuoteReserve >= graduationThreshold):
       factory.graduate(token) [atomic]
         success: CurveCompleted + GraduationSecured emitted in the same tx
         failure: swallowed, emits AutoGraduationFailed(token, gasleft)  // keeper/UI retry path
permissionless fallback: factory.graduate(token) by anyone; then factory.createGraduatedPool(token)
sell closes the same window: reverts CurveGraduated once readyToGraduate()
```

- The graduation trigger is the exhaustion of the sellable token allocation (a hard stop a buy cannot overshoot), equivalent to the quote threshold floor; partial-fill buys are clamped at the allocation boundary and priced for what they received.
- Deterministic opening: `reservedTokens = supply * phantomQuote / (phantomQuote + threshold)` is exactly the token balance the curve holds at the threshold, so the venue opens at the same price on every launch.

## 6. Known semantics cheat-sheet (verified against pinned source)

- **Launch fee**: `launchToken` requires `msg.value == launchFee` **exactly** (`if (msg.value != launchFee) revert LaunchFeeNotPaid()`); zero fee means value must be zero. The fee is forwarded to `memeHook.protocolFeeRecipient()` and reverts `FeeTransferFailed` if the forward fails.
- **expectedEconomics**: obtain from `previewLaunchEconomics(launchConfigId, quote)` (UNISWAP_V4) or `previewVenueEconomics(id, quote, venue)`; the preimage is `keccak256(abi.encode(supply, curveFeeBps, poolFee, tickSpacing, quotePolicyHash, quotePolicyVersion, phantomQuote, graduationThreshold, graduationQuoteCeiling, currentFeePolicy, venue, executor, executorCodehash, executorPolicyHash))` computed by `coordinator.previewEconomics`. `bytes32(0)` **waives** the pin; any other value must match exactly or `LaunchEconomicsMismatch(expected, actual)`. Reading and launching in separate txs leaves terms free to move — the pin converts silent repricing into a revert.
- **canLaunch**: `launchEnabled || whitelistedLaunchers[launcher]` — the exact predicate `launchToken` enforces on the initiating account (the wallet for direct launches; `originalDeployer` for the forwarder path).
- **Native MON quote**: `pairToken == address(0)` (checked via `curve.isNativeQuote()`). Curve `buy`: `msg.value == quoteIn` exactly, else `NativeValueMismatch`; ERC20 quote: `msg.value != 0` reverts `UnexpectedNativeValue`, and the credited amount is exact-delta verified both sides (`InexactQuoteTransfer` rejects fee-on-transfer). Curve `sell`: `token.approve(curve, tokensIn)` then the curve `transferFrom`s; payout follows the quote type. Approve target for ERC20-quote buys is the **curve**, not the factory.
- **Snipe tax / exemptions**: each launch snapshots factory `snipeTaxStartBps`/`snipeTaxSeconds` at creation (deployed values: 9900 bps / 15 s). The creator and creatorFeeRecipient are auto-exempted; the `address[]` overload adds up to 32 declared wallets (`ExemptionListTooLong`). Note the deployed `exemptFromSnipeTax` on the curve is a factory-gated minimal stub (no-op body in the pinned source) — exemptions beyond the launch-time list are not operative onchain in this build; the UI must not promise per-launch exemption management.
- **Launch configs**: `launchConfigCount()` + `getLaunchConfig(id)` return `(supply, curveFeeBps, phantomQuote, graduationThreshold, poolFee, tickSpacing, enabled)`; `poolFee` must be 0 (hook-managed fees), `tickSpacing ∈ (0, 32767]`, `supply ∈ [1e18, 2^127-1]`, `curveFeeBps ≤ 1000`, `creatorTaxBps ≤ maxCreatorTaxBps` (deployed 1000) and combined legs ≤ 2000 bps.
- **Quote admission**: `quoteRegistry.admitted(quote, venue)` returns the config or reverts `UnsupportedQuote`; `venueMask` bit 0 = UNISWAP_V4, bit 1 = KURU; `admitted` also re-validates decimals identity (native must be 18). Chain pin 10143 (`WrongChain`).
- **MarginAccount.deposit(address,address,uint256)** — the three args are `(user, token, amount)` (note: user first). Native MON is `token == address(0)` with `msg.value == amount` exactly; ERC20 requires `msg.value == 0` and pulls `amount` from `msg.sender` via transferFrom (approve MarginAccount) while crediting `user` — deposits for a different beneficiary are supported. (The 3-uint256 `deposit(uint256,uint256,uint256,address)` payable variant belongs to **KuruAMMVault**, not MarginAccount: `(baseDeposit, quoteDeposit, minQuoteConsumed, receiver)` with `msg.value >= baseDeposit` when token1 is native — protocol executor path only.)
- **OrderBook grids** (pinned Kuru parameter policy, verified in `KuruParameterPolicyV2` + market `getMarketParams()`): `sizePrecision = 1e8` and `pricePrecision = 1e8`, `tickSize = 1`, `minSize = 1e6`, `maxSize = 1e16`, `takerFeeBps = 30`, `makerFeeBps = 0`, vault `SPREAD = 100` (1%). Encoding rules per pinned source: `_price` is `uint32` with `0 < price < type(uint32).max` and `price % tickSize == 0`; `_size` is `uint96` with `minSize ≤ size ≤ maxSize`. Quote cost of an order = `ceilDivUp(price, size, sizePrecision) * quoteDecimalMultiplier / pricePrecision` (for the 18/18 MON markets: `quoteWei = price * size * 100`, rounded up). Conversion between the uint32 grid and real prices: real price (1e18 vault precision, as returned by `bestBidAsk`/`getVaultParams`) `P18` ↔ grid `P8 = P18 / 1e10` (and the code uses `tick = price * 1e18 / pricePrecision`); base `sizeWei = size * 1e18 / 1e8` (i.e. size 1e6 = 0.01 tokens). Always read the live market's `getMarketParams()` rather than hardcoding.
- **Order ID decoding**: `OrderCreated(uint40 orderId, address owner, uint96 size, uint32 price, bool isBuy)` is emitted for the *resting remainder* (an order that fully matches on placement emits only `Trade`s, no `OrderCreated`). `orderId` is `s_orderIdCounter + 1`, monotonic per market. Full order state via `s_orders(uint40)` → `Order{ownerAddress, size, prev, next, flippedId, price, flippedPrice, isBuy}`; an all-zero order (price == 0) means cancelled/cleaned. Fill status is inferred from the price-point head: if `head > orderId` (or head is NULL) the order was filled FCFS. Cancels emit `OrderCanceled(orderId, owner, price, size, isBuy)` / `OrdersCanceled(uint40[] ids, owner)` with `0` entries marking non-cancelled ids in the NoRevert variant.
- **Market order native bracket** (NATIVE_IN_QUOTE, the type used for MON-native launches, deployed with `OrderBookType == 2`): non-margin `placeAndExecuteMarketBuy` requires `msg.value >= cost(_quoteSize)` and `msg.value < cost(_quoteSize + 1)` — i.e. an exact bracket with dust, else `NativeAssetInsufficient`/`NativeAssetSurplus`; unfilled remainder is refunded in the same tx. Market sell on this market type requires `msg.value == 0` (base is ERC20). Margin variants (`_isMargin = true`) always require value 0 and debit the margin account.
- **Graduation trigger**: the curve graduates when its sellable token allocation is exhausted (`sellableTokens() == 0` ⇔ `realQuoteReserve() ≥ graduationThreshold`); the crossing buy attempts graduation atomically (`AutoGraduationFailed` on failure — retry via `factory.graduate`), and sells are refused in the ready-but-ungraduated window.
- **Addresses are exact-integer**: all amounts (launchFee, quoteIn, minTokensOut, price grids, share counts) are uint256/uint96/uint32 integers — the frontend/SDK must use exact bigint math, never floats.
