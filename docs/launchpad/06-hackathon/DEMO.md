# Hackathon Demo

**Status:** DRAFT  
**Owner:** Hackathon + Pitch  
**Authority:** Demo runbook

## Purpose

Define the live run order and fallback strategy.

## Requirements

- Pre-fund deterministic demo wallets and verify environment before judges.
- Use a launch with a practical threshold that can demonstrate graduation without unsafe parameter hacks.
- Keep primary live path, pre-deployed backup path and recorded proof.
- Show transaction hashes/market identity rather than only UI animation.

## Non-goals

- Never fake a successful integration.

## Acceptance criteria

- Demo completes within target presentation time and can be rerun.

## Evidence required

- Runbook, transaction links and backup recording.
