# Golden Path

**Status:** DRAFT  
**Owner:** Validation + Hackathon  
**Authority:** E2E acceptance path

## Purpose

Define one deterministic creator/trader flow used by product, testing and demo.

## Requirements

- Create -> index -> buy -> sell -> cross threshold -> graduate -> verify Kuru -> post-graduation trade.
- Specify actors, initial balances, token config, quote asset, threshold, expected state/events and checkpoints.
- Use the same scenario in local/staging E2E where practical.

## Non-goals

- Does not override protocol semantics.

## Acceptance criteria

- One command/runbook reproduces expected checkpoints.

## Evidence required

- Receipts, indexed entities and browser assertions.
