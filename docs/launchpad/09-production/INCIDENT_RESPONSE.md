# Incident Response

**Status:** DRAFT  
**Owner:** Release + Operations  
**Authority:** Operational specification

## Purpose

Define severity, ownership and safe operator actions.

## Requirements

- Classify contract/security, integration, data, frontend/backend and key incidents.
- Prefer containment and evidence preservation over ad-hoc contract actions.
- Document communication and postmortem requirements.

## Non-goals

- No undocumented privileged workaround.

## Acceptance criteria

- Procedure is reproducible by another operator.

## Evidence required

- Deployment/smoke/monitoring evidence.
