# Phase-1 financial collateral admission packet — 2026-09-28

**Decision state: PROPOSED, not frozen.** ADR-P06 recommends one standard, non-rebasing ERC-20. The Python reference rejects named exotic classes at construction; the Solidity research market checks zero addresses and `decimals()` in its constructor, then checks the incoming balance delta at `split`. That is not an onchain proof that a token will remain standard. This packet does not authorize a production asset or silently accept ADR-P06/P08/P09.

## Dual-role callback negative control

`research/contract-kernels/test/prediction/CallbackResolverLifecycle.t.sol` configures a callback-capable collateral token as its own resolver, which the constructor currently allows. During `split(1)`, `transferFrom` transfers the unit then calls `closeMint`, `beginResolution`, and `resolve(YES_WIN)` before returning. The outer `split` resumes and mints both outcomes while the market is already RESOLVED. `collateralAtResolution` is 0 but `collateralLocked`, both supplies, and physical collateral are 1. Redemption later pays 1. This does **not** show an unbacked payout; it falsifies the lifecycle ordering property. The test passes by asserting the failure. Artifact: `evidence/research/prediction/callback-resolver-lifecycle-2026-09-28.json`.

The existing `nonReentrant` on `split` blocks another `split`, not unguarded resolver transitions. Excluding callback tokens and prohibiting token/resolver role overlap are narrow admission controls, but an accepted architecture should also revalidate the state after an external token call or guard all relevant transitions. Which defense-in-depth rule is canonical needs a human decision and a wider callback search. No kernel function was edited here.

## Proposed qualification rule and falsification

Recommend a named, token-specific allowlist before activation: fixed settlement asset identity; documented decimals; exact inbound **and outbound** transfer behavior; no fee, rebasing, externally decreasing balance, or callback semantics the market must honor; explicit treatment of proxy upgrades, blacklist/freeze powers, and token admin risk. Check `physicalBalance >= remainingLiability` independently of `collateralLocked` at economically relevant boundaries, but do not pretend a momentary balance check can prevent a later external debit. The approved asset's code and governance trust must be documented, not inferred from the ERC-20 interface.

If accepted, align the Python admission oracle, constructor/factory admission path, Prediction tests, PRISM source-asset registry, and docs. If a named exotic asset is proposed, provide a stateful differential proof that both issuance and payouts preserve actual physical balance under its real transfer semantics. Until then every nonstandard class above remains unqualified. Current `PRED-CONTRACT-1` remains NOT PASS and `SOURCE-ASSET-INTERFACE-FREEZE` remains PROPOSED_NOT_FROZEN.
