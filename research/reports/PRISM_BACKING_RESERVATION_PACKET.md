## Component-backing decisions

The candidate requirement is `Req_i(S) = ceil(S * weightWad_i / (WAD * 10^(18-decimals_i)))` raw units for admitted decimals 0..18. Accepted mint must establish `backingRaw_i >= Req_i(S_new)` **after physical receipt and before liability issuance**. Requirement-delta release is `Req_i(S_old) - Req_i(S_new)`, so after a valid burn the prior margin remains. Historical Python, Solidity fixtures, bounded checks, and stateful invariants support these arithmetic properties within their declared domains; they do not qualify token behavior or ownership of prefunded assets.

## Reservation ledger: physical units versus paper units

`CandidateReservationLedger.deposit(asset, amount)` **only increments a mapping**. It does not call an ERC-20, check a custody address, or know the token's decimals. Its proven invariant is `sum_s reservedFor[s,a] <= ledger.balance[a]`, where `ledger.balance` is a caller-supplied paper number. A caller can credit paper balance without depositing one physical token. This kernel is useful for testing uniqueness arithmetic, but it cannot establish `sum_s reservedFor[s,a] <= PhysicalBalance[a]` as deployed. Treating it as a vault would counterfeit backing. The Python `ReservationLedger` also takes a logical deposit amount; it is a semantic oracle, not physical custody.

| Operation | Proposed caller / authorization | Precondition, transition, postcondition, failure |
| --- | --- | --- |
| `deposit(asset,q,beneficiary)` | Any payer for an explicit beneficiary or issuance reservation | Admitted asset, positive q, measured exact physical receipt. Increase attributed available backing by received q, emit payer/beneficiary/asset/q. Shortfall or callback violation reverts atomically; a direct donation remains unattributed until policy says otherwise. |
| `reserve(seriesId,asset,q)` | Admitted series controller or admission authority only | Verify series identity and beneficiary right, `q <= attributableAvailable`, and physical `balance >= totalReserved + q`. Increase series reserve and global total atomically; emit series/asset/q. Rejected reserve changes nothing. No arbitrary public reservation against another user's deposit. |
| `release(seriesId,asset,q)` | Owning series controller only, in a valid burn/transform path | `q <= series reserve`, decrease that reserve and global total exactly once, after liability reduction and before/with transfer. Emit series/asset/q. Rejection preserves state. A release must not mint a second spendable credit. |
| `withdraw(asset,q,to)` | Original attributable owner or a specifically accepted surplus owner | Only unreserved, attributed q; physical balance and any other liability remain covered after transfer. Emit owner/to/asset/q. Reject and preserve state if q touches any series reserve or a transfer returns short. No admin withdrawal of live backing. |

The two liabilities—per-series backing and global cross-series reservation—must derive from one authoritative custody state or a proven atomic custody reference. Avoid duplicating writable `backingRaw`, vault balance, and reservation totals across contracts without a reconciliation invariant. The normal path must make one physical unit unavailable to every other series once reserved. Cross-series deposit, reserve, release, withdraw, donation, and external loss need Python oracle, machine fixture, Solidity research kernel, positive/reject case, and stateful invariant **after** the production lifecycle is accepted. The current kernel only covers logical `deposit` and `reserve`; do not automatically port Python `release`/`withdraw` without the caller and ownership rules above.
